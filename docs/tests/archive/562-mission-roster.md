## Automated record — macOS, 2026-10-11

Branch: `fix/863-mission-crews`, based on the committed brief/spec at `dd762263`. Final candidate and both-platform CI are identified by the PR's head commit. All commands use this worktree's own `target/`.

Conversion orders stored session rows by SQLite `rowid` (registration order), which resume does not change, and keeps the first row per slot. An original same-handle crew slot with no session takes the failed-spawn fallback before consuming an unmatched session; its `added_at` must be at or before the mission start, so a later replacement cannot steal a deleted slot's identity. The version 2 file omits `added_at`, so returned roster slots use the mission start time for that DTO field. Status and summary displays use the current crew row; prompt copies remain frozen. Summary listing logs and skips a mission whose roster cannot be loaded or recovered, retaining healthy missions. Recovery writes only for a missing file or invalid JSON, preserving other read failures and valid JSON with an unsupported version or invalid shape.
