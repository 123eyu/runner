## Findings and failed attempts

1. **Model initialization race, introduced by this integration.** Installed API schema explicitly says `/api/model` may precede initial plugin settlement. The original one-shot `api --standalone GET /api/model` and native `models --standalone` returned empty, while the TUI later displayed 11 models. A private server held alive across authenticated native API requests reproduced 0 then 11 rows. The local fix owns a loopback stdio server and random child-only password, polls empty snapshots within the original 15-second budget, and reuses existing process-tree handling for clients and server cleanup. Runner's actual model picker then displayed the dynamic list. Model source description was updated.
2. **Normal Stop erased the key, introduced by the OpenCode watcher.** Public JSON showed the correct key before Stop and NULL after it; native API and a read-only inspection of this private OpenCode session table independently confirmed the history still existed. Resume therefore allocated a fresh key/home. A signal-guard hypothesis passed its stub but failed native Stop and was removed. The actual sequence is `PtyRuntime::stop` retiring the hook route before killing the CLI; receiver drain reports closed or failed as an error. OpenCode cleared identity for both. The final fix adds a read-only `is_retired` accessor through HookReceiver/HookFeed and uses it only in OpenCode: normal retirement returns the error without clearing identity, while live bridge failure/heartbeat expiry still clears it. Existing agents' drain/error behavior is unchanged. Native Stop now preserves the key and Resume opens the exact history.
3. **Provider prerequisite unresolved.** Two actual requests were rejected as quoted above. No available authenticated private account was supplied; an asynchronous request offered manual connection or an existing private configuration. The errors' attribution to provider policy versus native-client behavior has not been established by a matched external TUI control. Do not describe them as proven unrelated to Runner, or bypass the service restriction. Successful request status/outcome mapping remains unverified; the failed native requests settled to Ready with no outcome in Runner.

An initial shortened `--exact` filter ran zero tests and was corrected to the fully qualified test name.
