## Finding F1 — exited shell still appears as Active work

Repro: open an owned ordinary terminal in a split tab, focus it in Active, enter `exit 1` through native input, and leave its exited pane selected. The main surface says **Shell exited**, while Active displays **Terminals 1**, title **exit 1**, a dim terminal mark and no attention glyph. Jason independently captured that row and identified it as visually wrong. Closing the pane removes it (`31-exited-row-closed.png`).

Expected under Jason’s feedback: an exited/unavailable shell should not remain presented as active work merely because its exited pane is selected. The implementation’s selected-session exception at `crates/runner-app/src/surfaces/sidebar/active.rs:200` bypasses eligibility for every selected session, including this stopped shell. The spec expressly calls for retention when a viewed session becomes idle; this observed stopped case needs coder resolution. No baseline binary comparison was run, so this is a current candidate acceptance finding rather than an established historical regression.
