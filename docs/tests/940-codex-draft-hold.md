# #940 Codex draft-hold validation

## Scope and deterministic evidence

The selected behavior is terminal input tracking and the daemon's resulting delivery readiness. Native coverage is limited to the issue's immediate paste/Return scenario and relevant MIS-DRAFT-01, MIS-DRAFT-03 and MIS-MSG-04 variants. This is not a full live regression run. Codex is the required native runtime; unavailable native Windows and Claude control variants must be recorded separately from automated coverage.

Before the production change, `cargo test --locked -p runner-terminal --profile ci --test input_state_replay native_submit -- --nocapture` exited 101: both `native_submit_before_echo_releases_at_a_new_empty_composer` and `native_submit_after_echo_releases_at_a_new_empty_composer` expected Idle and observed Drafting. The starting production code was `be8feff6efc3aac4d069005223b23c59f98ab134` plus the mission brief. The preserved log is `/tmp/940-baseline-regressions.log`.

These deterministic tests establish two tracker defects: Return before an echo loses the probe's submission intent, and an unchanged submitted history row can keep a hold after a fresh empty composer appears. The second defect also occurs when the draft echo preceded Return, so preserving submission intent alone is insufficient. This does not establish the exact ordering of the historical native failures in #940. Native capture and delivery evidence remain necessary.

The correction retains native/generated submission origin and recognizes an empty composer at the terminal cursor, using the learned prefix, empty forms and placeholder style. A native probe's first nonempty echo stays Drafting while retaining submission intent; generated submissions keep their existing Submitted reporting. Empty-composer evidence can release a submitted history row even after it has been conservatively classified as a rejected submit. Return alone and elapsed time do not clear a draft. Subsequent content/edit input removes the old submission marker.
