# Runner roadmap

Snapshot as of 2026-10-17, after 0.16.4 and the reliable-delivery merge. [GitHub milestones](https://github.com/yicheng47/runner/milestones), [open issues](https://github.com/yicheng47/runner/issues) and [published releases](https://github.com/yicheng47/runner/releases) are the live sources. This file mirrors the current plan; historical milestone moves remain in GitHub and git history.

## Where the project is

- **Latest release:** [0.16.4](https://github.com/yicheng47/runner/releases/tag/v0.16.4), published 2026-10-17. Runner speaks English or Simplified Chinese, chosen in Settings → General and switched live across open windows ([#926](https://github.com/yicheng47/runner/pull/926)); macOS gains About Runner; Codex mission members keep receiving messages after a first turn that switched conversations or failed; and a paused mission hides its unread dot. The localization's final native retest was waived, and native Windows and an alternate OS language remain unverified in the [validation record](./tests/archive/565-i18n.md). [CI](https://github.com/yicheng47/runner/actions/runs/39020870349) and [release builds](https://github.com/yicheng47/runner/actions/runs/39020874662) passed on macOS and Windows.
- **Merged since the release:** durable, confirmed mission message delivery ([#921](https://github.com/yicheng47/runner/pull/921), closes [#907](https://github.com/yicheng47/runner/issues/907)), with its selected macOS QA in the [2026-10-16 run](./tests/runs/2026-10-16-macos.md). It ships in the next release.
- **Next:** finish mission delegation's follow-through in 0.16, building targeted messaging and the starting-chat return path on reliable delivery, then file preview and review in 0.17. The remote sequence is **web remote control → iOS companion → desktop-to-desktop SSH**.

## Delivery order

- **Delegation:** [#562](https://github.com/yicheng47/runner/issues/562) closed on 2026-10-16 after its roster, add/remove-role and empty-start phases shipped. Reconcile [#873](https://github.com/yicheng47/runner/issues/873) with the shipped no-crew behavior, then build the lead's verbs ([#916](https://github.com/yicheng47/runner/issues/916)) on that lead model. [#907](https://github.com/yicheng47/runner/issues/907)'s delivery guarantees merged in [#921](https://github.com/yicheng47/runner/pull/921) on 2026-10-17; targeted direct delivery ([#826](https://github.com/yicheng47/runner/issues/826)) and the starting-chat return path ([#748](https://github.com/yicheng47/runner/issues/748)) build on them, and both specs are reconciled with that delivery model before code. The [program record](./impls/archive/562-mission-spawn/README.md) retains the implementation history.
- **Review:** settle the [file-viewer design](./features/634-file-preview-and-review.md) before code and establish [#831](https://github.com/yicheng47/runner/issues/831)'s performance baseline before adding the viewer. Review comments reuse reliable delivery. Files and diffs stay read-only; editing, git writes and checkout management remain with the agent, git and the chosen editor.
- **Web first:** [#836](https://github.com/yicheng47/runner/issues/836) delivers host enrollment and an outbound relay connection, then a versioned encrypted companion protocol and a browser terminal with input and resize. The first complete flow works in desktop and phone browsers. Native iOS, push, LAN listeners and Tailscale do not gate it.
- **Reuse the remote foundation:** [#912](https://github.com/yicheng47/runner/issues/912) brings the same hosts and sessions to iOS after browser access works. [#808](https://github.com/yicheng47/runner/issues/808) then adds desktop-to-desktop execution over SSH; local launch preparation must run on the remote host, and a protocol mismatch must never stop that host's agents. Linux packaging is a separate track, not a prerequisite for Mac/Windows remote hosts.
- **Later tracks:** [#823](https://github.com/yicheng47/runner/issues/823) retains its [recorded Linux scope](./impls/briefs/823-linux.md): x86_64 app, daemon and CLI, tarball/deb/rpm packages, opt-in systemd user service, no updater in v1, and WSL verification. [#193](https://github.com/yicheng47/runner/issues/193) settles what a schedule launches and how reboot/missed-run behavior works before implementation.

## Product boundaries

`runnerd` owns local state and sessions; the desktop and CLI are clients. Remote access adds another authorized client to those same sessions. Session traffic is encrypted end to end between the host and client; the relay cannot read it. The public repository owns host behavior and the client protocol, while the web service and native phone app are developed separately. Connection and protocol work here is planned, not shipped.

The companion protocol is versioned independently of the local client protocol. A rejected remote client leaves the daemon and agents running. Local application updates retain their existing restart-and-resume contract; remote version negotiation must not reuse the local daemon replacement path.

Runner's own MCP server was removed in 0.11 and the CLI moved to runnerd's client protocol in 0.13.1. Mission coordination stays on the bundled `runner` CLI; Settings → MCP manages the user's servers. [#764](https://github.com/yicheng47/runner/issues/764) must verify pi's current native support before integration and must not restore Runner MCP registration.

New runtimes follow the [integration checklist](./arch/runtime-integration.md). Automated checks and native platform verification remain separate evidence: the [OpenCode record](./tests/archive/592-opencode-runtime.md) and [Antigravity record](./tests/archive/747-antigravity-followups.md) retain their Windows and inference-dependent gaps.
