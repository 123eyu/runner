The [program record](./impls/archive/562-mission-spawn/README.md) retains the implementation history.
- **Remote control:** [#836](https://github.com/yicheng47/runner/issues/836) is released with two routes together, Tailscale for users worldwide and the invite-only hosted service for mainland China (Jason, 2026-10-18). Its parts are ordered by how easily each is built and tested: host enrollment and the outbound relay connection ([#951](https://github.com/yicheng47/runner/issues/951), merged into the `nightly-remote` umbrella in [#945](https://github.com/yicheng47/runner/pull/945) and closed on 2026-10-19), the versioned companion protocol and client trust ([#952](https://github.com/yicheng47/runner/issues/952)), the end-to-end channel with live browser terminals ([#953](https://github.com/yicheng47/runner/issues/953)), then Tailscale on the same protocol and channel ([#954](https://github.com/yicheng47/runner/issues/954)). Work lands on the umbrella with test builds on the `remote-nightly` release, and the umbrella reaches `main` once both routes pass. The first complete flow works in desktop and phone browsers; native iOS, push and same-network listeners do not gate it.
- **Review:** settle the [file-viewer design](./features/634-file-preview-and-review.md) before code and establish [#831](https://github.com/yicheng47/runner/issues/831)'s performance baseline before adding the viewer. Review comments reuse reliable delivery. Files and diffs stay read-only; editing, git writes and checkout management remain with the agent, git and the chosen editor.
- **Reuse the remote foundation:** [#912](https://github.com/yicheng47/runner/issues/912) brings the same hosts and sessions to iOS after browser access works. [#808](https://github.com/yicheng47/runner/issues/808) then adds desktop-to-desktop execution over SSH; local launch preparation must run on the remote host, and a protocol mismatch must never stop that host's agents. Linux packaging is a separate track, not a prerequisite for Mac/Windows remote hosts.
- **Later tracks:** [#823](https://github.com/yicheng47/runner/issues/823) retains its [recorded Linux scope](./impls/briefs/823-linux.md): x86_64 app, daemon and CLI, tarball/deb/rpm packages, opt-in systemd user service, no updater in v1, and WSL verification. [#193](https://github.com/yicheng47/runner/issues/193) settles what a schedule launches and how reboot/missed-run behavior works before implementation.

## Product boundaries

`runnerd` owns local state and sessions; the desktop and CLI are clients. Remote access adds another authorized client to those same sessions. Session traffic is encrypted end to end between the host and client; the relay cannot read it. The public repository owns host behavior and the client protocol, while the web service and native phone app are developed separately. Connection and protocol work here is planned, not shipped.

The companion protocol is versioned independently of the local client protocol. A rejected remote client leaves the daemon and agents running. Local application updates retain their existing restart-and-resume contract; remote version negotiation must not reuse the local daemon replacement path.

Runner's own MCP server was removed in 0.11 and the CLI moved to runnerd's client protocol in 0.13.1. Mission coordination stays on the bundled `runner` CLI; Settings → MCP manages the user's servers. [#764](https://github.com/yicheng47/runner/issues/764) must verify pi's current native support before integration and must not restore Runner MCP registration.

New runtimes follow the [integration checklist](./arch/runtime-integration.md). Automated checks and native platform verification remain separate evidence: the [OpenCode record](./tests/archive/592-opencode-runtime.md) and [Antigravity record](./tests/archive/747-antigravity-followups.md) retain their Windows and inference-dependent gaps.
