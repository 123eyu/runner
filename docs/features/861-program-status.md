Agent-hook changes, Settings controls and the Claude Code blocked-versus-PermissionRequest comparison belong to [#1051](https://github.com/yicheng47/runner/issues/1051) and are outside this feature.

## Protocol contract

Sources checked on 2026-10-27: [protocol introduction](https://mitchellh.com/writing/program-status-osc7501) and [revision 0.4 specification](https://www.superlogical.com/rex/docs/build/program-status). Runner answers every local daemon-owned PTY, including shell tabs, direct agent chats and mission sessions; no mounted pane is required. App mirrors do not answer or independently publish status.

The probe is `ESC ] 7501 ; ? ST`. Runner's exact reply is `ESC ] 7501 ; ? ESC \` (`\x1b]7501;?\x1b\\`). Omitting capability lists advertises the fixed states idle, working, done, blocked and error, and kinds permission, question and auth. The reply enters the existing ordered terminal-events channel at the probe's position, before a following primary DA query is parsed, including queries split across reads. It never includes report text.

Reports are `OSC 7501 ; pairs ST`, with `pairs := pair (":" pair)*`, `pair := key "=" value`, `key := [a-z]+`, `value := [A-Za-z0-9_.,+/=-]*`. Surrounding ASCII whitespace is trimmed. BEL (`0x07`) and `ESC \` terminate sequences. Arbitrary PTY chunk boundaries are supported. CAN/SUB abort; ESC followed by anything other than ST aborts the current OSC. Malformed pairs are handled independently. OSC-like bytes inside other terminal control strings are not independent reports.

Malformed pairs (missing equals, empty/invalid key, invalid value bytes) are skipped; unknown keys are ignored, duplicate keys use the last valid pair. `state` is required and must be idle, working, done, blocked, error or clear. `kind` accepts permission/question/auth only for blocked; unknown kinds are absent. `progress` is an integer 0–100 for working/blocked, otherwise absent. `app` is `[A-Za-z0-9_.+-]{1,32}`; invalid app is absent. `msg` and `title` are standard base64 UTF-8, with optional padding. A decoding failure, invalid UTF-8, or any decoded U+0000–001F/U+007F–009F control rejects the whole report. Text is plain text, never markup; direction overrides and common invisible formatting characters are removed for external status labels.

Hard limits are checked before applying a record, including repeated and unknown pairs: whole OSC-through-terminator sequence 4096 bytes; key 16 bytes; msg 2732 encoded/2048 decoded bytes; title 256 encoded/192 decoded bytes; app 32 bytes; id 128 bytes, at most 8 slash-separated segments of 1–32 `[A-Za-z0-9_.+-]` bytes. An invalid id rejects the report rather than addressing root. Runner stores at most 256 records, evicting the least recently updated record when necessary. Each accepted report replaces its complete record; absent id addresses root. App inherits from the nearest ancestor with app. Clear removes its record and descendants, or all records at root. RIS clears every record; DECSTR and screen switching retain them. An observed OSC 133 D (command finished) followed by A (prompt start), with no intervening C (command start), clears working/blocked (and idle) while done/error survive. Bare A does not clear records: pi 1.4.0 uses A/B/C around transcript redraws. This interoperability guard requires D→A shell-return evidence or an explicit program clear; A-only shell integrations retain active evidence until clear/reset/PTY exit. The command-boundary meanings and D→A shell sequences are documented by [kitty shell integration](https://sw.kovidgoyal.net/kitty/shell-integration/). Process exit clears Runner's active program evidence and native waits; the turn outcome can remain in the stopped session snapshot.

## Session state and precedence

The current report set is reduced to one existing session status: blocked takes priority over working, then error, done and idle; within a state the most recently updated record wins. No records releases OSC ownership to the output baseline. Working maps to Working, idle to Idle, blocked to Needs you with msg in the existing detail label, done to Idle/Completed, and error to Idle/Failed. Kind supplies the existing wait reason. Repeated blocked reports retain the interaction identity and age until the selected wait changes or resolves.

An established live hook bridge owns status. Accepted hook observations replace OSC status; later OSC reports cannot override them. Bridge failure releases hook ownership and invalidates cached records and any partial report, while preserving split probe framing: only a fresh OSC report can reclaim it. Output heuristics cannot overwrite active OSC evidence. Sequence numbers reject stale terminal evidence; stopped/replaced launches reject late publication. OSC reports do not arm, consume or fabricate unread responses or completed-response attention. The existing Codex native-attention parser remains intact, including its overlay on hooked Codex sessions.

Wire compatibility uses additive, defaulted program-status evidence on AgentObservation, retaining the existing baseline source wire value so older app/CLI clients can deserialize status. New clients recognize exact stream evidence and omit the estimated-activity marker. The reducer tracks OSC ownership separately from hook ownership. Native blocked interactions use the existing delivery gate's NeedsYou hold; resolution wakes readiness without clearing an independent draft.
