# 723 — Grok Build runtime

> Tracking issue: [#723](https://github.com/yicheng47/runner/issues/723). Grok only; Cursor shipped in 0.15.0 under [its own spec](./723-cursor-agent-runtime.md).
> Status: in development on `feat/723-grok-build`. Probed against grok 1.0.50 (`c58f321264ba`, stable) on macOS with a grok.com (SuperGrok) sign-in, 2026-10-11.
> Contract: [Runtime integration](../arch/runtime-integration.md). Every P0 row there applies; this spec records grok's native mechanism for each and the decisions Runner makes.

## Motivation

Run xAI's Grok Build CLI (`grok`) as a Runner runtime in role chats, runtime-only chats and crew missions, using the person's existing grok.com sign-in.

## What the CLI offers

Evidence from `grok --help`, `grok models`, `grok inspect`, the user guide the CLI extracts to `~/.grok/docs/user-guide/` on launch, the on-disk session store, and bounded live CLI probes on 2026-10-11. Probe results and native-app evidence are recorded separately in [the validation record](../tests/723-grok-build-runtime.md).

| Need | Native mechanism in 1.0.50 |
| --- | --- |
| TUI and first turn | `grok [OPTIONS] [PROMPT]`; the positional prompt is the initial prompt for the interactive session. Fullscreen alternate screen by default, mouse reporting and bracketed paste on (`--no-alt-screen` and `--minimal` opt out). The positional text was exact with and without `--verbatim` in the live probes. |
| Assigned key | `-s/--session-id <UUID>` for a new conversation; must be a valid UUID that does not exist yet. Grok mints UUIDv7 itself. |
| Resume | `-r/--resume <id>`; UUID-shaped values always mean ids, never titles. |
| Fork | `--resume <src> --fork-session -s <new UUID>`. |
| Model and effort | `-m/--model <id>`; `--reasoning-effort` (alias `--effort`) works in the TUI. `grok models` prints `Default model: <id>`, then `* <id> (default)` and `- <id>` lines: `grok-4.7`, `grok-4.7-build-fast`, `grok-4.6`, `grok-4.5` on this account. Per-model effort menus live in `$GROK_HOME/models_cache.json` at `models.<id>.info.reasoning_efforts[].id` (`low`, `medium`, `high`, `xhigh`; `grok-4.5` lacks `xhigh`), refreshed by the CLI from its models endpoint. |
| Permissions | `--permission-mode default\|acceptEdits\|auto\|dontAsk\|bypassPermissions\|plan`; `--always-approve` (alias `--yolo`) is `bypassPermissions`. Deny rules and hooks still apply under it. |
| Folder trust | Gates project hooks, MCP, LSP, project instructions (`AGENTS.md`) and project skills together. Store: `$GROK_HOME/trusted_folders.toml`, entries `[folders."<path>"]` with `trusted = true` and `decided_at = <epoch>`. `--trust` is hidden from `--help` but accepted by the parser; the guide says it persists the grant. |
| Hooks | Claude-compatible JSON. Global `$GROK_HOME/hooks/*.json` files are always trusted and merge with project, `~/.claude/settings.json` and `~/.cursor/hooks.json` sources. Events: `SessionStart` (matcher is the source), `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `Notification` (`permission_prompt` fires only while a permission UI waits; `idle_prompt`), `Stop` (genuine completion; a second `Stop` at session end carries `reason` `channel_closed` or `shutdown`), `StopFailure`, `StopCancelled` (Ctrl+C, declined permission, turn limit), `SessionEnd`, subagent events. Every payload has `sessionId`, `cwd`, `permissionMode` and, inside a turn, `promptId`. Hooks fail open and only an explicit deny blocks. `Stop` and `PostToolUse` default to a 600 s timeout. No launch flag adds a hook file, and the `GROK_CONFIG` overlay cannot add hooks. |
| Session store | `$GROK_HOME/sessions/<URL-encoded cwd>/<id>/`; a group name over 255 bytes becomes a slug plus hash with a `.cwd` file. `summary.json` holds `info.id` and `info.cwd`. `GROK_HOME` defaults to `~/.grok`. |
| Skills | `.grok/skills` and `.agents/skills` at each tier (cwd, repo, home), plus the Claude and Cursor roots. `grok inspect` already lists Runner's managed `runner` and `runner-dev` from `~/.agents/skills`. `[skills] disabled` in `config.toml` is a native toggle. |
| MCP | `[mcp_servers.<name>]` in `$GROK_HOME/config.toml` (`command`, `args`, `env`, `enabled`, `url`, `headers`, `type`, …). Also reads `~/.claude.json` and `~/.cursor/mcp.json` by default. |
| Native defaults | `[models] default` and `[models] default_reasoning_effort` in `$GROK_HOME/config.toml`. |
| Version and updates | `grok --version` prints `grok 1.0.50 (c58f321264ba) [stable]`. Self-updating (`installer = "internal"`, `grok update`, `cli.auto_update`, `GROK_DISABLE_AUTOUPDATER`). Install: `curl -fsSL https://x.ai/cli/install.sh \| bash`, Windows `irm https://x.ai/cli/install.ps1 \| iex`. |
| Usage | `grok usage` reports per-session tokens and cost. The TUI `/usage` modal shows a weekly allowance and reset, but the read-only weekly billing response exposed the reset without a used fraction or used/limit pair. Plain billing returned monthly credits, not this weekly allowance. Subscription usage stays unavailable in Runner; see the validation record. |
| Coexistence | Jason's `~/.grok/hooks/orca-status.json` (Orca) registers every event, `PreToolUse` included. Runner leaves it alone. |

## Decisions

1. **Identity.** Runtime key `grok`, display name Grok, command `grok`, description "xAI Grok Build CLI". The install link is the official install page if one resolves, otherwise the getting-started instructions above. Enabled by default (`default_enabled: true`), per Jason's 2026-10-11 policy change: Cursor and Grok are default-on; TRAE CLI is opt-in. Native Windows remains unverified. Managed skill root `.agents/skills`, so `RUNNER_SKILL_ROOTS` is unchanged. Settings → Skills reads `.grok/skills` and `.agents/skills` with no toggle; toggling `[skills] disabled` is a follow-up. Version from `grok --version`; no Update button and no npm package, because grok updates itself. Icon: the official Grok mark as a monochrome `currentColor` inline SVG with a source comment, like Cursor's; if no official vector is reachable, a neutral glyph already in the asset set, named in the PR.

2. **Environment.** `GROK_HOME` resolves from the role environment, then the captured login-shell environment, then `~/.grok`; shell discovery captures `GROK_HOME`. Discovery, the session probe, the hook installer and trust all use that one resolution. Do not set `GROK_DISABLE_AUTOUPDATER` unless a probe shows a launch-time update prompt that blocks the TUI or races the first turn; record the result either way.

3. **Prompt.** Positional first turn with Cursor's channels (`system_prompt: false`, `resend_persona_on_fresh: true`): a fresh spawn sends the composed persona, coordination and goal as the prompt; a resume sends none. `--rules` is not used, because its TUI and resume behavior is unverified and the first turn meets P0.3. Pass the prompt after `--` so leading option-like text remains positional. The native hook and persisted user-message chunks retained a leading `/`, `@` mentions, multiline text, non-ASCII characters and quotes exactly, with and without `--verbatim`; Runner therefore omits that flag. Long bodies use the existing delayed first-turn path.

4. **Permissions.** Claude Code's shape: offer Default, Accept edits, Auto and Bypass, mapped to `--permission-mode default|acceptEdits|auto|bypassPermissions`; `--always-approve` and `--yolo` also match Bypass. Strip `--permission-mode` (both spellings), `--always-approve`, `--yolo`, `--trust` and `--sandbox <profile>` from stored role args under the existing rules. Missions use `--permission-mode bypassPermissions`.

5. **Folder trust.** Pass `--trust` on every launch, as Cursor does: the person chose the folder in Runner, and an unanswered trust prompt hides `AGENTS.md`, project skills and project MCP and can race the first turn. The live TUI probe persisted the canonical scratch cwd in `$GROK_HOME/trusted_folders.toml` and delivered the first turn without a trust dialog. No trust-file seeding is needed.

6. **Model and effort.** The static catalog offers Default model and Default effort only. Discovery (P1) runs the effective executable's `grok models` through the existing background and cache pipeline with a 15 s timeout and parses the `*`/`-` lines; a failure keeps the cached or static list. A model's `supported_efforts` come from `models_cache.json` when the file parses and lists that id; otherwise the model offers Default effort only. Never invent a level. Pass `-m <id>` for an explicit model, and `--reasoning-effort <level>` only when the effective model lists that level. Model precedence for this gate is explicit model, `GROK_DEFAULT_MODEL` from the effective launch environment, native `[models] default`, then the discovered default. Capture `GROK_DEFAULT_MODEL` from the login shell along with `GROK_HOME`; role values override captured values. Native defaults also read `default_reasoning_effort`.

7. **Conversation identity.** A fresh spawn assigns a UUID v4 with `-s`. Resume passes `--resume <key>` only for a stored UUID-shaped key. The existence probe looks for `$GROK_HOME/sessions/*/<key>/summary.json` whose `info.cwd` equals the launch cwd, so it never reimplements the directory encoding. A blank TUI created its assigned session directory and summary before the first message; Runner retains its guarded missing-history behavior. Fork (P2) uses `--resume <src> --fork-session -s <new>`, with `native_fork: true`: the probe recalled the source token in the fork, changed the fork's token, and then resumed the source and recalled its original token.

8. **Status hooks and rekey, macOS and Linux.** At daemon start, when the resolved `$GROK_HOME` directory exists, atomically write `$GROK_HOME/hooks/runner-status.json`. Never create `$GROK_HOME` and never touch another file in it. One file serves both release and development Runner, so each command takes the reporter path from `RUNNER_HOOK_EXECUTABLE` (already in `hook_env`) and does nothing when it is unset: grok started outside Runner runs a no-op. Commands survive spaces in the path (`Application Support`), print nothing on stdout, exit 0, and set `timeout` to 2 explicitly. Verify that grok passes its environment to hook processes and how its own `$VAR` expansion treats an unset variable.

   Register `SessionStart`, `UserPromptSubmit`, `PostToolUse`, `PostToolUseFailure`, `Notification` (`permission_prompt|idle_prompt`), `Stop`, `StopFailure` and `StopCancelled`; no `PreToolUse`. Map `UserPromptSubmit` to a started turn, tool events to working, `permission_prompt` to a surfaced approval wait, `Stop` with `reason` `end_turn` to completed (ignoring the session-end `Stop`), `StopFailure` to failed and `StopCancelled` to interrupted. Track started `promptId` values per conversation and ignore reports for known older turns; reset that tracking on rekey. Reports without a prompt ID and terminal reports for a never-seen bash-mode prompt remain valid backstops. `idle_prompt` clears interactions and returns to idle without claiming a completed turn. `SessionStart` carries the active `sessionId`: rekey through the existing generation-checked path when it differs from the stored key. The native sources observed were `new` and `load`; `/new` and `/clear` emitted `new`, while CLI resume, picker resume, `/home` followed by picker selection, and `/fork --no-worktree` emitted `load`. Switching back to an already loaded dashboard session emitted no `SessionStart`; its next `UserPromptSubmit` carried the selected UUID. That event also recovers a changed key through the same generation guard. A switch followed by stopping before any further prompt leaves the last reported key unchanged, a native-event limitation. Never rekey to a subagent's session. An operation that leaves no evidence is a documented limitation, not a guess.

9. **Windows.** Launch, permissions, trust, models and explicit resume are shared code. Hooks stay off on Windows, because grok runs hook commands under pwsh, Windows PowerShell or Git Bash and that path is unverified, so Windows uses the terminal baseline and does not follow in-TUI conversation switches. Native ConPTY stays unverified until a JASONPC smoke; ask Jason before installing grok there.

10. **MCP settings (P1).** Settings → MCP reads and edits `[mcp_servers.<name>]` in `$GROK_HOME/config.toml`, reusing the Codex TOML client's translation and splicing where the native fields match and preserving unrelated content. Verify a written entry with `grok mcp list` against a temporary `GROK_HOME`.

11. **Subscription usage (conditional deliverable, added 2026-10-11).** Implement one `Week` window only when a single read-only response supplies both weekly usage and its reset. The scratch `/usage` debug probe and authenticated GET requests found that `/billing?format=credits` supplies `config.currentPeriod` with `type: USAGE_PERIOD_TYPE_WEEKLY` and `start`/`end`, but omits `creditUsagePercent` and weekly used/limit fields. That field name comes from the CLI binary's `BillingConfig` field list. Proto3-style omission of a zero primitive is plausible: the response has proto-style enums and explicit zero money wrappers. A recheck at 10:02 UTC after the day's probe turns still omitted the field, while `/usage` displayed 0% and the same reset. No turns were spent forcing non-zero usage. `/billing` supplies monthly `used`/`monthlyLimit` and a different period end; `/user?include=subscription` supplies identity/tier, and `GET /auth/check_subscription` returned 404. Those results do not establish a weekly usage value, so `usage: false` remains. Follow up when a non-zero `creditUsagePercent` response can be compared with the TUI. After that field is proven, an omitted percent may mean 0 only in a well-formed response with `currentPeriod`, with a one-line comment explaining the default. Never scrape the TUI or drive a hidden CLI. A future UsageSource must consume the access token read-only, make no refresh/write/logging calls, fetch in a bounded background request and leave expired/401 credentials unavailable. On-demand/prepaid credits are not usage windows.

Out of scope: an Update button, skill toggles, `--rules`, headless and ACP modes (`-p`, `grok agent`), worktree and sandbox flags, plugins, and grok's own dashboard as a Runner surface.

## Implementation Phases

1. Identity, catalog, icon, detection and override, environment, permissions, trust, prompt, model and effort argv, assigned key, resume and the session probe; every enumerating test and golden updated, with the other runtimes' argv unchanged.
2. Model discovery, native defaults, version, skill roots, Settings copy, and `README.md` with `README.zh-CN.md`.
3. The hook installer, reporter mapping, rekey and status, and a recorded terminal fixture.
4. The MCP client, then fork if the probe proves it.
5. The validation record and the smoke.
6. The conditional subscription-usage probe and implementation decision, per decision 11.

## Verification

Focused tests cover argv for fresh, resume, fork, model, effort, permission and trust launches with the other runtimes unchanged; role-arg stripping including `=value` forms; the `grok models` parser on captured, sanitized output and the cache reader (missing, malformed, unknown id); effort gating; `GROK_HOME` resolution; the session probe including a cwd mismatch; the hook file's contents and installer (no `$GROK_HOME` writes nothing, foreign files are untouched, rewriting is idempotent); reporter mapping including the session-end `Stop`, `StopCancelled`, a stale generation and a subagent session; and an MCP round trip on a temporary config. A real grok first-turn terminal fixture replays in the existing harness.
