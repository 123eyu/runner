# 562 — implementation log

Dated record of how [#562](https://github.com/yicheng47/runner/issues/562) has moved. The current state is in [README.md](README.md).

- **2026-09-18** — Jason set the model: a mission is a container of agents, its coordinator inside (a crew lead) or outside through a general `runner` CLI. The CLI shipped first as #648.
- **2026-10-10** — The spec was rewritten against the `runnerd` code: a crew is not a prerequisite for a mission, a mission can start from a single role, and roles can be added to or removed from a running mission. The lead's verbs and outside seats moved to Follow-ups.
- **2026-10-11** — Jason replaced a crew row per mission with a roster file in the mission's directory. #562 became the parent of #863 and #748, and #704 closed into it. Mission 1 implemented Phase 1 and merged as [#868](https://github.com/yicheng47/runner/pull/868), fixing #863.
- **2026-10-12** — Jason folded the app phase into Phases 2 and 3, so each ships its GUI with its CLI, and reopened Phase 3's interface. 0.15.2 shipped Phase 1.
- **2026-10-12** — Phase 2's frames were drawn in `design/specs/562-mission-spawn.pen` and reviewed: the remove control became the `log-out` icon behind a confirmation, a mission adds configured roles only, the feed shows `runner` as `system` with a seeded pixel avatar, and the Add role dialog was corrected to the shipped Start chat layout. Signed off and committed to `main` as `2db4e953`.
- **2026-10-12** — The Phase 2 plan was written. Reviewing it with Jason settled that agents learn the team from their inbox and `runner mission show` rather than a new command; that the lead should become optional, filed as [#873](https://github.com/yicheng47/runner/issues/873) with Phase 2 kept from assuming a lead; that each session must be independent, because a newcomer crashing at boot would otherwise reap a running team; and that membership bounds only broadcasts, so a directed message is never dropped.
- **2026-10-12** — Session independence was split out as mission 2 on the codex trio. Review was clean in one round. QA's live pass waited on Jason's approval of a single Codex trust entry for its `/tmp` test folder; the approval reached the mission through `runner mission answer`, and the entry was removed after QA's cleanup. QA passed IND-1 to IND-3, MIS-CREW-01 and MIS-LIFE-01; IND-4 was not run, because the app cannot express a failing runtime, and the automated test covers it. Merged as [#874](https://github.com/yicheng47/runner/pull/874) after green CI. `feat/562-add-remove-roles` was rebased onto it, and mission 3's brief was written.
- **2026-10-12** — Checking the Phase 2 plan against the code found three gaps. `runner msg read` builds an agent's inbox from the whole log itself, so a newcomer reads the team's earlier broadcasts whatever the bus projects; Jason accepted that while mission logs stay short, and decision 4, the tests and the live checks now say so. `SessionManager::kill` does nothing for a session that has not started, so removing a slot still in the spawn queue would leave it running off the rail, and Archive can only cancel a spawn flag that already exists; decision 15 refuses add and remove while any spawn is pending and has add register its cancel flag before it inserts the session row.
- **2026-10-12** — Reviewing what a running mission still reads from its role, Jason settled that roles and crews are templates and that a session records its whole launch definition at spawn, not only the runtime, model, effort and speed #870 records. The roster never copies a role's configuration. Filed as [#878](https://github.com/yicheng47/runner/issues/878), a sub-issue of #562 and the prerequisite for m3; the spec's "What is copied, and when" (`140de276` on `main`) has the rules, replacing the follow-up that copied roles into the roster.
- **2026-10-13** — Jason detached [#748](https://github.com/yicheng47/runner/issues/748) from #562 as unrelated; the issue, the spec (`188a2719` on `main`) and this record no longer count it as part of the program. #878's PR, [#881](https://github.com/yicheng47/runner/pull/881), had green CI with live QA waived; Jason asked for that QA as a codex trio mission. After QA's Codex trust question held a third mission, he made Runner's trust entry for a live run's own folders pre-approved (`ae8a8cd8` on `main`).
- **2026-10-13** — #881 merged after QA's focused macOS pass, with the feed's stopped-mission divider fixed in the same PR at Jason's request. `feat/562-add-remove-roles` was rebased onto it. The Phase 2 plan's line numbers were refreshed, its text updated for #874 and #881 (an added slot's overrides are what Restart rebuilds from, and a removed slot's resume refusal sits at the mission-context lookup), MIS-ROSTER-01 joined the live checks, and two lessons from #881's QA were added.
